# 営業スライド（日本のBtoB向け）

`brief.md` と `knowledge/frameworks.md` を読む。

## 大前提
日本のBtoBでは、**商談相手（担当者）と決裁者が違う**ことが多い。
資料のゴールは「担当者が、あなたがいない会議でこの資料だけで上司を説得できること」。

## 標準構成（12〜15枚）
1. 表紙（提案先名・提案タイトル＝相手のメリットで書く）
2. 本日のご提案の要点（結論を先に、3行）
3. 貴社の現状と課題（ヒアリング内容。不明なら `【商談でヒアリング】` の穴あき）
4. 課題を放置した場合の損失（数字で。根拠がなければ試算式を示す）
5. 解決策の全体像（図解指示）
6. 選ばれる理由3つ（ポジショニング）
7. 導入事例（同業種・同規模を優先。社名掲載許可がなければ「製造業A社（従業員300名）」）
8. 費用と費用対効果（松竹梅プラン、回収期間の試算）
9. 他の選択肢との比較表（自社・競合・内製・何もしない）※競合名は出さず「一般的なA社サービス」でも可
10. 導入スケジュール（稟議〜導入〜定着まで）
11. サポート体制・セキュリティ（情シスに聞かれる項目：データ保管場所、ISMS/Pマーク、SLA）
12. よくあるご質問
13. 次のステップ（具体的な日付と行動）

## 出力形式
各スライドについて：
```
### スライドN：タイトル
- 見出し（1行・結論）：
- 本文（箇条書き3つまで）：
- 図・グラフの指示：
- 話すこと（トーク原稿、60秒以内）：
```
最後に「想定される反論と切り返しトーク」を5つ付ける（例：「予算がない」「今のやり方で困っていない」「上に相談します」）。

`output/YYYYMMDD_slide_<提案先>.md` に保存。PowerPoint化を求められたら pptx 作成も提案する。
