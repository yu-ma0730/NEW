# ページ診断・改善

対象（`pages/` 内のファイル、または貼られた文章）、`profile.md`、`brief.md`（あれば）、`knowledge/frameworks.md` を読む。
ページの種類・紹介案件・読者にしてほしい行動が分からなければ、最初に3つまで質問する（`pages/_template.md` の項目）。

## 1. 30秒診断（最初に要点だけ）
- このページは **誰の・どんな悩みに** 答えているか（1行で）
- 読者がこのページに来た時点での **顧客の認識度**
- 一番の強み1つ・一番の問題1つ

## 2. 詳細チェック
| 観点 | 判定 ◎○△× | 原文の該当箇所 | 改善案 |
|---|---|---|---|
| 検索意図・投稿の狙いに合っているか | | | |
| 冒頭3行で「自分のための記事だ」と分かるか（滑り台効果） | | | |
| 実体験・一次情報があるか（自分の写真・使った感想・数字） | | | |
| 紹介案件を選ぶ理由が書いてあるか（リーズン・ホワイ） | | | |
| デメリット・向いていない人を書いているか（日本では信頼に直結） | | | |
| 比較・選び方があるか（読者の「失敗したくない」に応えているか） | | | |
| リンクの位置・文言・数（多すぎ／少なすぎ） | | | |
| スマホで読みやすいか（1文の長さ・改行・表） | | | |
| 「PR」「広告」表記があるか（ステマ規制） | | | |
| 法令・ASP規約上の問題表現 | | | |

## 3. 書き直し
- 問題の大きい順に、**書き直した文章そのもの**を出す（指摘だけで終わらない）
- 書き手の口調・体験は残す。体験していないことを体験したように書き換えない
- 実体験が足りない部分は `【あなたの体験を入れる：例）申込にかかった時間】` と穴あきにする

## 4. 最後に
- 一番効果がありそうな修正1つと、その効果を確かめる数字
- `/check` 観点の懸念点
- `output/YYYYMMDD_page_<ページ名>.md` に保存
