# メール／LINE ステップ配信

`brief.md` と `knowledge/frameworks.md`（プロダクトローンチ・心理トリガー・バリューラダー）を読む。

## 1. 最初に確認（不明なら質問する）
- 配信媒体：LINE公式アカウント／メール／両方
- ゴール：個別相談の予約／商品購入／来店／セミナー参加
- 登録の入口（特典）は何か

## 2. シナリオ設計
まず全体図を表で示す：

| 日 | 目的 | 使う型・トリガー | 内容の一言 |
|---|---|---|---|
| 0（登録直後） | お礼・特典配布・自己紹介 | 返報性 | |
| 1 | 共感・悩みの言語化 | 新PASONA の P・A | |
| 2 | 気づき（常識の否定） | エピファニー・ブリッジ | |
| 3 | 解決策の全体像・お客様の事例 | 社会的証明 | |
| 4 | 提案・オファー | リーズン・ホワイ、リスクリバーサル | |
| 5 | FAQ・不安解消 | | |
| 6 | 締切リマインド（**実在する締切のみ**） | 希少性 | |

日数・通数はゴールと価格に合わせて調整する（高額ほど長く）。

## 3. 本文の書き方
- **LINE**：1通 200〜400字目安、吹き出し2〜3個に分割、絵文字は控えめに1〜2個、リッチメッセージ／ボタンの文言も提案。配信は **平日 12時台・20〜21時台** を初期値とし、テストを推奨
- **メール**：件名は30字以内で2案ずつ。プレヘッダーも書く。本文は1通1メッセージ
- 毎通、最後に「返信してください」「スタンプで教えてください」など**双方向の一言**を入れる（日本ではブロック率低下に効く）
- 売り込みの通は全体の2〜3割に抑える

## 4. 仕上げ
- 配信停止・ブロックが増えそうな箇所の指摘
- 法令セルフチェック（特商法：メール広告はオプトイン・配信停止方法の表示が必要＝特定電子メール法）
- `output/YYYYMMDD_step_<テーマ>.md` に保存
