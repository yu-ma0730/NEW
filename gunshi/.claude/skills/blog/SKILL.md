# ブログ記事

`profile.md`、`brief.md`（またはその案件の `projects/<案件>/brief.md`）、`memory/MEMORY.md`、`knowledge/platform-rules.md`、`knowledge/frameworks.md` を読む。

## 1. キーワードと読者
- 狙う検索キーワードを1つ決める（「〇〇 おすすめ」「〇〇 比較」「〇〇 評判」「〇〇 デメリット」など、買う直前の言葉を優先）
- そのキーワードで検索する人の **認識度** と、知りたいことを3つ書く
- 上位記事の文字数・見出しを調べられる場合は調べる。調べられなければ、ユーザーに確認してもらう項目として書く

## 2. 構成（先に見せて了承をもらう）
```
タイトル（32字前後。キーワードを前半に）
冒頭：本記事はアフィリエイト広告を利用しています。
導入（読者の悩み → この記事で分かること）
## H2 …
### H3 …
## 比較表 / 選び方
## デメリット・向いていない人
## まとめ（誰に何をすすめるか）
```

## 3. 本文
- **5,000字まで**（改行は数えない。目安4,500字）。超えたら削る
- アフィリエイトリンクはすべて **`URL PR`**（URL の直後に半角スペース＋PR）。URL が無ければ `【案件リンク】 PR`
- 体験していないことは書かない。体験が要る所は `【あなたの体験：〇〇】` と空ける
- 料金・キャンペーンには `（YYYY年MM月時点・公式サイトで確認）` を付ける
- 新PASONA の流れで、デメリットと向いていない人を必ず入れる

## 4. 仕上げ
- 文字数（改行を除く）と、すべてのリンクが `URL PR` になっているかを数えて報告する
- `/gate` の15の関所で確認する
- `output/YYYYMMDD_blog_<キーワード>.md` に保存
