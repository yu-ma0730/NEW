# LP・セールスレター

`brief.md`、`knowledge/frameworks.md`、あれば `output/` 内の最新 concept を読む。

## 1. 型の選択
| 状況 | 型 |
|---|---|
| 一般消費者向け・悩み解決型（王道） | 新PASONA |
| 高額・検討期間が長い・教育が必要 | QUEST |
| 創業ストーリーや変化の物語が強い | PASTOR（増幅は控えめに） |
| BtoB | 新PASONA＋比較表＋導入事例＋FAQ厚め |

選んだ型と理由を冒頭で1行伝える。

## 2. 構成（新PASONAの場合の例）
1. **ファーストビュー**：キャッチ（認識度に合わせる）＋サブキャッチ＋権威/実績1つ＋CTA
2. **Problem**：顧客の言葉で悩みを3〜5個（「こんなお悩みありませんか？」）
3. **Affinity**：「その気持ち、よく分かります」＋作り手の失敗談（エピファニー・ブリッジ）
4. **Solution**：解決策と**リーズン・ホワイ**（なぜ効くのか・なぜこの価格なのか）
5. **Proof**：実績・お客様の声・メディア掲載（brief にあるものだけ）
6. **Offer**：価格、特典、保証（リスクリバーサル）、松竹梅プランがあれば真ん中を推奨
7. **Narrow**：「こんな方におすすめ／おすすめしない方」（日本では「おすすめしない方」が信頼を生む）
8. **Action**：CTA（「無料で相談する」など、心理的ハードルの低い言葉）
9. **FAQ**：買う前の不安を5〜8個（解約方法・支払い方法・サポートは必ず入れる）
10. **特商法表記・プライバシーポリシーへのリンク位置**を指示

## 3. 日本向けの書き方
- 1文40字以内目安、スマホで3〜4行ごとに改行
- 見出しごとに「この見出しだけ読んでも話が通じる」ように（流し読み対策）
- CTAボタンは3〜4箇所。文言の候補を3つ出す
- 写真・図解の指示を `［画像：〇〇の写真］` の形で入れる

## 4. 禁止事項
- brief にない数字・お客様の声を作らない（必要なら `【要確認】` で穴あき）
- 偽の締切、リセットされるカウントダウン、根拠のない「通常価格〇〇円→今だけ」は書かない
- 健康・美容系は効果効能の断定をしない

## 5. 仕上げ
- 末尾に「使用した型」「法令セルフチェック（/check の観点で懸念点を列挙）」「A/Bテストするならこの2箇所」を付ける
- `output/YYYYMMDD_lp_<テーマ>.md` に保存
